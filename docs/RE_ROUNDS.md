# Reverse-engineering rounds (stock-firmware mapping)

Working plan for the REA/Ghidra mapping effort. Any session can pick this up: check the status column, resume the next round.
Tooling: [REA_SETUP.md](REA_SETUP.md). Map: [ATLAS.md](ATLAS.md) (generated by `tools/atlas/gen.py` from `tools/atlas/atlas_data.py`).

**Rules for every round**
- Max 2 agents at once, each REA/Ghidra run capped at 8G.
- Analysis only: no builds, no camera or SD card, no commits.
- Each agent writes `docs/RE_<TOPIC>.md` plus `tools/atlas/new_<topic>.py` (entries in atlas_data.py format). The lead merges these into atlas_data.py, reruns gen.py and marks the round done here.
- Trust the atlas. Verify only the bytes you depend on.
- If a question stalls, write it up and stop.
- Decompiler output and long listings go to `~/ep7fw-private/decomp/<topic>/`, never into the repo. Docs carry our own prose only ([RE_PRIVATE.md](RE_PRIVATE.md)).
- After merging a round: rerun `tools/atlas/gen.py`, refresh the named project with ApplyNames (RE_AUTONAME.md §5; only when no agent is mid-session), then run `tools/backup_nas.sh`.
