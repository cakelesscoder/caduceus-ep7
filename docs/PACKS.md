# Preset look packs

The Control Panel ships its built-in looks as **preset packs**. Users start from one (**New › Start from …**) or mix
looks from several into the pack they export (**+ Add look › From a preset pack…**). A preset pack is camera-neutral:
it uses the shared look format, and each export target translates it like any other pack (AGENTS.md, "One Control Panel").

| Pack | File | Status |
|---|---|---|
| Standard 1.1 | `webapp/src/data/packs/standard-1.1.json` | default for new users |
| Standard 1.0 | `webapp/src/data/packs/standard-1.0.json` | the library before packs, unchanged; generated by `npm run gen-library` from `bundles/library_v3.json` + `sim/recipes` |
| Tokyo Nights, Tokyo Days, Autumn, Summer, Winter, Film Noir 1.0 | `webapp/src/data/packs/<id>.json` | mood packs (below) |

## Format

A pack file is a normal pack (`schema: "caduceus-pack/1"`, `looks`, `slots`) plus:

- `id`: stable, for example `standard-1.1`. Looks added from the pack remember it in their app-only `origin`, as `pack:<id>:<look name>`, so **Reset look** restores that pack's values. A plain `origin` (packs saved before preset packs existed) means Standard 1.0.
- `name` and `version`: shown together as the label, for example "Standard 1.1".
- `notes` (optional): one line, shown in the picker (the pack's description).
- `kind` (optional): `"library"` (the default: a full look library, Standard) or `"mood"` (a small themed set, below).
  `packs.ts` exposes it as `PresetPack.kind`, with `presetsOfKind()`.
- `stamp` (Standard 1.0 only): the old library build hash. The app's migration of saves from before packs still keys on it.

Older apps and other panels read the file as a plain pack. `id`, `version`, `notes` and `stamp` are ignored, and `origin` is never exported, so share codes (`pk1_` and look codes) are unchanged.

**Packs are frozen once released.** A revision becomes a new file with a new version, so a look saved from 1.0 keeps
its 1.0 values. To add a pack, add the JSON file and list it in `webapp/src/packs.ts` (`PRESETS`, newest first).
`webapp/tests/packs.test.ts` checks that every pack exports valid E-P7 `LOOKS.BIN` and `BUNDLES.BIN` files and an OM-3 file.

**Grain, NR and Sharp** belong to each profile and are never set by a look. 1.1 keeps 1.0's `grain` values (the
look's old NR field: the E-P7 ignores it since v0.27, and the OM-3 reads it as the look's NR) and adds no `film_grain`.

### Split tone pass

Split tone carries casts that differ between shadows and highlights, which WB (one global shift) can't. Strength 1 is one
step, about 2.5 % of the range on the strongest channel at the shadow (1/3) or highlight (2/3) peak. In the preview maths
(`preview.ts` on a neutral grey ramp) that is 3 to 5 Cb/Cr levels on 8-bit grey, against about 1 level for one WB step.
Where split now carries a look's global cast, the WB moves one step back so the look doesn't double up. Skin tones
(light and dark test patches) move by 3 Cb/Cr levels at most.

Colours are the camera wheel's (`split.ts`): Yellow, Orange, Orange-red, Red, Magenta, Violet, Blue, Blue-cyan, Cyan,
Green-cyan, Green, Yellow-green. "—" means off (strength 0).

## Mood packs

Small themed collections of 4 to 6 looks (`kind: "mood"`), each with starter slots so loading one gives a ready card.
Some looks are Standard 1.1 copied unchanged ("= 1.1"). The others are new looks or variants for the mood, built the
way 1.1 builds its looks:

- Split tone only where the stock has a shadow or highlight cast.
- Halation only on rem-jet-free film (CineStill). Still C-41 film gets a plain glow at most.
- `grain` (the old NR field) follows 1.1's convention: off for fine slides and slow film, fine for typical negatives,
  film for fast or grainy stocks.
- No `film_grain`, no `profiles`: Grain, NR and Sharp stay the user's profile settings.

Mono looks (as in 1.1) carry only the colour filter, contrast and tone advice. The E-P7's mono rendering comes mainly
from the profile, so Tri-X Push and Pan F 50 differ from Tri-X 400 mostly by their advice.

**Sanity check.** The preview maths (`preview.ts renderLook`, advice on), run on a neutral grey ramp (32..224) and on
light and dark skin patches, keep every new look inside Standard 1.1's range:

- Grey cast at most 5.7 Cb/Cr levels, except 800T Neon (15, like CineStill800's 15.7: its WB A−2 and red bloom are
  the stock's tungsten cast).
- Skin moves by at most 12 Cb/Cr levels.
- The lifted looks raise the black point the most: 400H Overex lifts a 32 grey to 63 and Sun Bleach to 63, against 58
  for 1.1's Pro 400H.

## Split tone on the E-P7: what carries it

- **Panel and shared format:** looks carry `split {sh_color, sh, hl_color, hl}`, and `pk1_` pack links keep it. Look codes (`1…`–`8…`) have no split digits, so a shared single look loses it. The editor now has a Split tone group, and the preview applies `bendSplit`.
- **BUNDLES.BIN (works):** for firmware option v0.32 or later, a look placed in a COLOR slot writes slot +62/+63 (`format.ts` `placeLook`). Standard 1.1's starter COLOR1 (Classic Neg) carries split this way.
- **LOOKS.BIN (v0.32, built, `patches/looks_split`):** the split sits in the v3 record's name tail. The file stays
  version 3 and the same size.
  - **Names are at most 12 characters** on every camera, so the name and its NUL end by record +60. The panel cuts a
    longer name from a file, code or link to 12 and says so. All writers already capped at 12 (panel `NAME_MAX`,
    `tools/ep7_library.py`); the longest built-in names (`CineStill800`, `Vision3 500T`) are exactly 12.
  - Record **+61** = Shadows, **+62** = Highlights, packed exactly like slot +62/+63: low nibble colour 0..11, high
    nibble strength s4 −5..5 (`sh_color | (sh & 15) << 4`). 0 = no split. +63 stays NUL.
  - Panel: `lookRecord` writes +61/+62 only for the firmware option **v0.32 or later** and only for a colour look with a
    non-zero, valid split. Older options write 0, so the file stays byte-identical and older `fm_check` (which rejects
    any non-zero byte after the name's NUL) still accepts it. Opening a LOOKS.BIN reads the split back.
  - Firmware, on load (`ls_chk` at fm_load's `call fm_check`): the file's CRC is checked first. Each record must have
    +61/+62 = 0, or +60 = 0 with both bytes in range (the split_tone reader's nibble rule). Then the bytes move to a
    stash past the 2560 B the Movie / AP pages copy, the records get 0 there, and the CRC is rewritten. fm_check then
    runs unchanged. A bad byte, or split behind a 13–15-character name, leaves the file as read, so fm_check rejects
    it and the camera stays stock for the Film page, as with any bad LOOKS.BIN.
  - Firmware, on a Film pick (`ls_pick` at sl_pick's tail, real P only):
    - a library look writes its two bytes to slot +62/+63; 0 clears the profile's split;
    - Own and Stock write the slot's snapshot bytes, so they get back the split the profile had before the Film page
      touched it;
    - Movie / AP Film pages (P2 / P3) and a slot without a snapshot: nothing.
  - So a file without split (every file before v0.32) loads as before, and its looks clear split on a pick.
  - `lt_mod` still compares slot bytes 0..48, so split never sets `*`.
- **Without looks_split (split_tone alone, checked in the emulator):** no pick touched +62/+63, because u_apply copies slot bytes 0..49 only
  (`patches/v025` `PICK_BOUND`). The profile kept its split, which the v0.32 CHANGELOG line "picking a film clears that
  profile's split tone" got wrong. `patches/looks_split/verify.py` P shows both.
